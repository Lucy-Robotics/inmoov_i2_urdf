# InMoov i2 (this package)

## What this repository implements today

**`inmoov_i2_urdf`** ships the **InMoov i2** robot description under `description/robot_description/`, vendored from [Artur-Fedjukevits/inmoov_ros2](https://github.com/Artur-Fedjukevits/inmoov_ros2/tree/main/src/inmoov_description) (`src/inmoov_description`, commit `73c584b`). Mesh URIs were rewritten from `package://inmoov_description/meshes/` to the parent `mesh_dir`; `description/urdf/inmoov.urdf.xacro` adds a fixed `base_node` root above the i2 `stand_link`. Meshes are CC BY-NC 4.0 (see `description/robot_description/LICENSE-ASSETS.md`).

The hardware YAML drives the i2 from two Arduino Mega 2560 boards (`board_class: i2c_pwm_only`), each behind a Nervo board: **`mega_left`** (head and expression servos on its PCA9685, left arm and head rotation on the Nervo ribbon) and **`mega_right`** (both hands, wrists and the stomach on two PCA9685s, 0x41 and 0x40, plus the right arm on the Nervo ribbon). `pca_addresses` lists each board's chips and `mega_pins` its ribbon pins: `physical_pin` 1..16·N are the PCA9685 outputs, then 16·N+1.. the `mega_pins` in order. `configs/default.yaml` follows the PoC robot's wiring with every row disabled; the PoC's calibrated config and poses live on the `robot/poc` branch. Set each board's `serial_id` to its Mega's USB serial number, then activate the config in the LCP with the board selected (or `pixi run firmware-flash-mega <board>`): the firmware tables are generated from the YAML. Calibrate each joint in the LCP and enable it once it is checked on the robot.
